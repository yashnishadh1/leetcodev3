Contributing

Thanks for considering a contribution.

Before You Start

• Check existing issues and pull requests to avoid duplicate work.
• For a bug, include the relevant browser, Tampermonkey version, and a sanitized error message.
• Never include GitHub tokens, cookies, session credentials, or other secrets in an issue or pull request.

Development Guidelines

• Keep changes focused and explain the problem they solve.
• Preserve the existing JavaScript style and avoid adding dependencies unless necessary.
• Do not hard-code tokens, API keys, or private user data.
• Keep GitHub permissions to the minimum required.
• Treat missing submission verdicts as Unknown; do not assume they indicate acceptance.
• Avoid automatic submission loops or repeated submissions without explicit user action.
• Test changes on a non-sensitive test repository or a LeetCode problem where appropriate.

Pull Request Process

1. Create a branch for your change.
2. Describe the problem, the proposed fix, and any behavior changes.
3. Include testing steps and results.
4. Update documentation when setup, configuration, or user-visible behavior changes.
5. Ensure that no secrets or unrelated files are included.
6. Submit the pull request for review.

Reporting Bugs and Requesting Features

Use the repository’s issue templates when available. Include reproducible steps and expected versus actual behavior.
